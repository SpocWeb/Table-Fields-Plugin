# Table Fields

> 还是你的 Markdown 表格，但现在你能**点**它了——勾选复选框、从下拉里选、日期和金额也显示得清清爽爽，
> 全都在你的笔记里完成。

[English](README.md) · **中文** — [工程文档 ›](ENGINEERING.zh-CN.md)

Table Fields 给每一**列一个含义**。告诉它"这列是复选框""这列是状态下拉""这列是金额"，你那张普通表格
就变成了一个能像小型电子表格一样操作的东西。而关键承诺是：**底层它依然只是一张普通的 Markdown 表格**。
关掉插件，你的笔记和原来一样清爽可读。没有数据库、没有隐藏文件、不绑架你的数据。

## 下拉、日期、金额和复选框直接在笔记里渲染

![下拉字段让表格取值保持统一，同时日期、金额和复选框仍然清楚可读。](assets/readme/01-dropdown-field.png)

- ☑️ **能点的复选框**——直接在表格里点一下标记完成。
- 🔽 **下拉选择**——从固定选项里选状态或分类，取值不会再乱飘。
- 💲 **金额、百分比、日期都显示得体**——金额带货币符号右对齐，日期按你本地格式，百分比对齐好看。
- 🖱️ **右键一列就能设定它是什么类型或按它排序**——不用去翻设置页。
- 👀 **阅读时和编辑时都能用**——两种模式下控件都在。
- 🧹 **绝不绑架**——磁盘上永远是一张纯 Markdown 表格。

## 用类型行或一段注释给每列声明字段类型

有三种写法可以描述各列，效果相同，插件三种都能读。

### 写法一：表格里的 `__` 类型行

在表头的 `---` 行下面，写一行各列的类型，
再为每个下拉选项写一行。
这些单元格必须以 `__` 开头，
插件靠这一点认出它们，即使你按某一列排序过表格也一样。
选项行里没有选项的单元格写一个 `-`。
升序排序时，`__` 单元格排在最前，`-` 单元格紧随其后，
所以类型行留在最上面，选项行紧挨在它下面。

此外，列头的右键类型菜单里也有排序命令，
它们会把类型行和选项行保留在最上面。

后面接数据行：

```markdown
| Task           | Status   | Due        | Done  |
| -------------- | -------- | ---------- | ----- |
| __text         | __select | __date     | __    |
| -              | __Todo   | -          | -     |
| -              | __Doing  | -          | -     |
| -              | __Done   | -          | -     |
| Draft PRD      | Doing    | 2026-07-22 | [x]   |
| Review designs | Todo     | 2026-07-24 | [ ]   |
```

插件会隐藏类型行和选项行；没有插件时，它们显示为普通的表格行。你标记表格或修改列类型时，插件写入的
就是这种格式。

### 写法二：表格上方的 HTML 注释

你写（或让它生成）这样一小段注释。注释和表格之间要空一行，否则 Obsidian 不会把它渲染成表格：

```markdown
<!-- table-fields id="tasks" v="1"
cols:
  - {name: "Task",   type: "text"}
  - {name: "Status", type: "select", options: ["Todo","Doing","Done"]}
  - {name: "Due",    type: "date"}
  - {name: "Done",   type: "box"}
-->

| Task           | Status | Due        | Done |
| -------------- | ------ | ---------- | ---- |
| Draft PRD      | Doing  | 2026-07-22 | [x]  |
| Review designs | Todo   | 2026-07-24 | [ ]  |
```

注释在阅读视图里不可见，表格本身也不会多出额外的行。

无论哪种写法，在笔记里它都会变成一张表：**Status** 是下拉，**Due** 显示成整洁的日期，**Done** 是一个
能点的真复选框。点一下，改动就直接存回表格里。

### 写法三：表格上方的元数据表

一张可见的表，表头第一格是 `Column`，描述它下面那张表的各列。
它可以有 `Type`、`Options`、`Unit`、`Scale`、`Description` 这几列，顺序不限；
其他列会保留，插件不理会。
两张表之间只能有空行和一行标题。
`Type` 为空表示 `text`；`box` 是复选框。
`Scale` 是一个普通数字，即所显示数值的除数：
`4.2`、Scale 为 `1000`、Unit 为 `EUR`，表示 4 200 EUR。
`Options` 用逗号分隔（`Todo, Doing`；选项里的逗号写成 `\,`）；
插件只读取它们，写入选项时只写 `__` 选项行。
数据表里的选项行（以及带键的行 `__unit:ms`、`__scale:1000`，每个键一行）与写法一相同，只是不需要类型行：

```markdown
Columns of Runs:

| Column | Type   | Unit | Scale | Description                 |
|--------|--------|------|------:|-----------------------------|
| Min    |        | ms   |       | fastest run                 |
| Cost   |        | EUR  |  1000 | cost of all runs            |
| Status | select |      |       | state of the job's last run |
| Done   | box    |      |       | reviewed by me              |

| Min | Cost | Status  | Done |
|----:|-----:|---------|------|
| -   | -    | __Todo  | -    |
| -   | -    | __Doing | -    |
| 340 |  4.2 | Doing   | [ ]  |
```

元数据表本身仍是一张普通的可见表。
插件把各列的描述、单位和比例显示为列头单元格的提示文字，
在阅读视图里还把单位显示为后缀（`Cost [k EUR]`；Scale `1000` 显示为 `k`，`1000000` 显示为 `M`，其他为 `×<比例>`）。
单元格的值不会被重新格式化。
同一列的类型、选项、单位或比例在这里和 `__` 行里都有时，以 `__` 行为准；
描述只存在于这里。
在列头菜单里修改列类型时，会写到该列类型原来所在的位置，
否则写入元数据表，绝不写成注释。

### 复选框列有几种写法

复选框列可以写成 `box` 或 `checkbox`，两者含义相同。在类型行里，单独一个 `__` 是 `__box` 的简写，
所以 `__`、`__box` 和 `__checkbox` 是等价的。类型行里的空单元格表示 `text`。

![右键列头即可选择这一列的 Table Fields 类型。](assets/readme/02-field-type-menu.png)

## 下拉选项在 Source mode 里直接改

切到 **Source mode**，编辑 `select` 列的选项。
用类型行时，每个选项是该列选项行里一个以 `__` 开头的单元格，
例如 `__Low`、`__Medium`、`__High`；
选项比行多时，再加一行选项行，
其他列写 `-`。
选项单元格留空的旧表格仍然可用，
但在编辑模式下排序时，空单元格会排到类型行上面。

用注释时，编辑该列的 `options` 列表，
例如 `options: ["Low","Medium","High"]`。

改完切回阅读视图或 Live Preview，
下拉列表就会使用新选项。
小提示：如果新选项没有立刻出现，退出这篇 note
再重新打开一次，让渲染刷新。

![在 Source mode 里修改 select 列的 options 列表即可编辑下拉选项。](assets/readme/05-edit-dropdown-options.png)

![复选框字段可以直接在表格里勾选，并把值写回 Markdown。](assets/readme/03-checkbox-field.png)

## 关掉插件后仍然是可读的 Markdown 表格

- **它不是数据库。** 像 Obsidian Bases 那样会把每一行变成一篇独立笔记；Table Fields 让一切都留在
  *一篇笔记的一张表*里。
- **它不是另一个电子表格。** 有些表格工具把你的数据存成一段你再也看不懂的代码；Table Fields 从不这样，
  它始终是一张纯表格。
- **随时可以关。** 关掉后你的笔记仍是干净可读的 Markdown 表格，数据不丢，也能在任何别的 App 里读。

![关闭 Table Fields 后，笔记仍然是一张 Markdown 表格；US$ 这类只用于显示的格式会退回成磁盘里的纯数字。](assets/readme/04-markdown-fallback.png)

## 从任意普通 Markdown 表格开始

1. 写一张普通的 Markdown 表格。
2. 把光标放进去，运行命令 **"Table Fields: Mark table under cursor as Table Fields"**——它会看你的
   数据、自动把各列配好。
3. 想改某一列？**右键它的表头**，选类型（文本、复选框（box）、下拉、日期、金额、百分比）。
4. 想排序？同一个菜单里有 **Sort ascending**（升序）和 **Sort descending**（降序）。类型行和选项行留在
   最上面；数据行按该列的类型排序（数字按数值、日期按时间、未勾选的复选框在已勾选之前、下拉值按选项
   顺序），空单元格排在最后。
   没有类型、但所有单元格都是数字（如 `4.2`、`1,5`、`60%`）的列也按数值排序，`-` 单元格排在最后。

就这样。点你的复选框和下拉，改动会自动存回笔记。

## 每种字段类型只整理一种值

- **复选框列**——把一列"完成 / 未完成"变成能点的方框。
- **下拉（select）列**——给一列一组固定选项（比如 *Todo / Doing / Done*），大家用词统一。
- **金额列**——你只填纯数字，显示时保留两位小数并右对齐；
  选项行写了货币代码（如 `__EUR`）时带货币符号，没有代码时不显示符号，只显示该列的单位（如有）。
- **百分比列**——保持成简单的 `60%` 文本，对齐好扫读。
- **日期列**——按标准格式存储，按你本地日期风格显示。
- **右键设定**——直接在表格上改任意列的类型或按它排序，不需要配置页。

## 让你的 AI 读写你的表格

Table Fields 内置了一段给 AI 的现成提示词。打开 **设置 → Table Fields → AI skill**，点
**Copy to clipboard**，粘贴给 Claude、ChatGPT 或任意助手——它就懂 Table Fields 的语法，能帮你读取、
新建、修改表格了。

![Table Fields 设置里的 AI skill 标签页，带一个 Copy to clipboard 按钮和现成的提示词。](assets/readme/06-ai-skill-in-settings.png)

## 制表符填充让表格更小，并在弹性制表位编辑器里对齐

Obsidian 和大多数表格插件会用空格把每个单元格补齐到列宽。
这样在纯文本编辑器里也能读，但每改一个长值就要重新补齐整列，
空格也可能占掉文件的很大一部分。
而 Rubberband 这类弹性制表位编辑器会把以制表符结尾的单元格对齐。
Table Fields 可以按这种形式写入表格。

在 **设置 → Table Fields → Options → Tab before each cell's closing pipe** 打开它。
默认关闭。

### 哪些内容会被重写

只要 Table Fields 自己写入一张表格，就会整体重写这张表格：
勾选复选框或选择下拉值（Live Preview 和 Reading view）、
排序、在表头菜单里修改类型，以及 **Mark table** 命令。
每一行都会重写，包括表头、`---` 行以及类型行和选项行；
如果上方有元数据表，也一并重写。
单元格的改动和新的填充是同一步，一次撤销即可同时还原。

你自己编辑过的表格，在光标和焦点离开后也会重写。
Obsidian 的表格编辑器（点进单元格时打开）会用空格填充每一行，并按 `---` 行对齐单元格；
离开表格时，Table Fields 会把这些空格改回制表符。
这是单独的一步：离开表格后的第一次撤销会恢复空格。

### 单元格如何写入

- 每个单元格在 `|` 前以**一个制表符**结尾，开头的 `|` 后保留一个空格。
- **文本左对齐**，即使 `---` 行把该列设为居中（`:---:`）或右对齐（`---:`）。
- **数字列右对齐**，用空格补齐到该列最宽的单元格。
  类型为 `currency`、`percentage` 或 `timespan` 的列，
  或所有数据单元格都是数字（如 `12`、`4.2`、`1,5`、`60%`）的列，都算数字列
  （`-` 和空单元格不计）。
  它的 `---` 单元格的短横线会拉长或缩短到同样宽度，冒号保留。
- **空单元格**写成一个空格加制表符。
- Obsidian 的显示对齐仍由 `---` 行决定，变的只是源码。

### 示例：带类型的表格

示例中 `→` 表示一个制表符。
这张表格用空格填充，就像 Obsidian 写入的那样：

```markdown
| Task           | Status   | Amount     | Share   | Done |
| :------------: | -------- | ---------: | ------- | ---- |
| __text         | __select | __currency | __percentage | __ |
| -              | __Todo   | __EUR      | -       | -    |
| -              | __Done   | -          | -       | -    |
| Draft PRD      | Done     | 1200.00    | 60%     | [x]  |
| Review designs | Todo     | 59.5       |         | [ ]  |
```

勾选一个复选框后，文件内容是：

```text
| Task→| Status→|     Amount→|        Share→| Done→|
| :------------:→| --------→| ---------:→| ------------→| ----→|
| __text→| __select→| __currency→| __percentage→| __→|
| -→| __Todo→|      __EUR→|            -→| -→|
| -→| __Done→|          -→|            -→| -→|
| Draft PRD→| Done→|    1200.00→|          60%→| [x]→|
| Review designs→| Todo→|       59.5→| →| [ ]→|
```

`Task` 虽然被 `---` 单元格设为居中，仍然左对齐。
`Amount`（currency）和 `Share`（percentage）右对齐到各自最宽的单元格，
这里是类型单元格。
表格从 422 个字符缩小到 369 个。
弹性制表位编辑器显示为：

```text
| Task           | Status   |     Amount |        Share | Done |
| :------------: | -------- | ---------: | ------------ | ---- |
| __text         | __select | __currency | __percentage | __   |
| -              | __Todo   |      __EUR |            - | -    |
| -              | __Done   |          - |            - | -    |
| Draft PRD      | Done     |    1200.00 |          60% | [x]  |
| Review designs | Todo     |       59.5 |              | [ ]  |
```

### 示例：按值识别的数字列，以及元数据表

这里的数据表没有类型行，类型来自上方的元数据表：

```markdown
| Column | Type   | Unit | Scale | Description      |
|--------|--------|------|------:|------------------|
| Cost   |        | EUR  |  1000 | cost of all runs |
| Done   | box    |      |       | reviewed by me   |

| Run    | Cost | Code | Done |
|--------|-----:|------|------|
| first  |  4.2 | 7    | [ ]  |
| second | 12   | x1   | [x]  |
| third  | -    | 9    | [ ]  |
```

勾选一个复选框后，两张表格都会重写：

```text
| Column→| Type→| Unit→| Scale→| Description→|
| --------→| --------→| ------→| ----:→| ------------------→|
| Cost→| →| EUR→|  1000→| cost of all runs→|
| Done→| box→| →| →| reviewed by me→|

| Run→| Cost→| Code→| Done→|
| -------→| ---:→| ------→| ------→|
| first→|  4.2→| 7→| [ ]→|
| second→|   12→| x1→| [x]→|
| third→|    -→| 9→| [ ]→|
```

`Cost` 只含数字（和一个 `-`），所以即使没有类型也右对齐。
元数据表里的 `Scale` 也因同样原因右对齐。
`Code` 保持左对齐，因为 `x1` 不是数字。

### 哪些内容保持不变

- 你既没有编辑、也没有通过插件修改的表格，即使光标经过它们。
- 没有类型行、注释或元数据表的普通 Markdown 表格。
- 代码块里的表格，以及表格上方的配置注释。
- 在 Reading view 或其他程序里编辑的表格，直到插件下一次写入它们。
